## 1. A control file changed. Read this first.

The band's standing rule is that fixture integrity holds and a change to a
fixture is said before it is made. **This story changed two of them**, and
there was no way to do the story without it.

- `forecast-app/tests/run_bundle_fixtures/run_bundle.golden.json`
- `forecast-app/tests/run_bundle_fixtures/run_manifest.golden.json`
- their two recorded hashes in `forecast-app/tests/fixture_hashes.json`

**Why it was unavoidable.** The advice strings are engine output. The run
bundle records the engine's output verbatim, so any change to a "Do this"
sentence moves the bundle, and the manifest carries a sha256 of each stage
payload, so it moves too. The strings cannot be changed anywhere else.

**Why this is not the move the rule forbids.** Both files are derived
artefacts, regenerated by the repository's own generator,
`tests/generate_run_bundle_goldens.py`, and never edited by hand. The
generator re-verifies the quality result against `expected_quality.json`
before it writes anything, so the engine's judgements are checked against an
untouched expectation on the way through. Definition of done item 5 names
golden regeneration as a build session's work. No `expected_*.json` file and no
fixture CSV was touched, and no schema shape changed, so no version bump was
due.

**What actually moved.** The regenerated files were compared leaf by leaf
against the committed ones:

| File | Leaf values | Changed | Added | Removed |
|---|---|---|---|---|
| `run_bundle.golden.json` | 1453 before, 1453 after | 24 | 0 | 0 |
| `run_manifest.golden.json` | 210 before, 210 after | 5 | 0 | 0 |

Of the 24 in the bundle: **13 `action` strings, 3 `detail` strings**, and 8
hashes that follow from them (three stage payload digests, two content
fingerprints, the manifest digest and the bundle digest). The manifest's 5 are
all hashes.

**Nothing else moved, and it is provable rather than asserted.**
`forecast-app/tools/verify_golden_copy_only.py` takes a baseline git ref, reads
the committed goldens out of it, compares them with the working tree and exits
non-zero on the first thing it cannot account for. Six independent checks:

1. **Shape.** Both documents are flattened to leaf paths, dicts by key and
   lists by index, and the two path sets must be identical. Nothing added,
   nothing removed, no list resized, and no list reordered, since a reordering
   moves values between indices and check 2 then catches it.
2. **Non-string leaves.** Every number, boolean and null must be identical.
   This is done by type rather than by field name, so a numeric field nobody
   thought to list is still covered. This is the check that answers "no numeric
   value, no count, no share, no flag".
3. **String leaves.** Every differing string is bucketed by field name, and the
   set of names must be a subset of the declared copy fields plus the declared
   hash fields. A changed `reason`, `code`, `band`, `sku` or `decision` fails
   here even though it is a string.
4. **Hashes are derived, not edited.** Every digest is recomputed from the new
   content with the application's own `verify_bundle`, `exact_manifest_hash`
   and `content_fingerprint`. A hand-edited hash cannot survive it. The per
   stage `output_ref` digests are taken over sanitised payloads and so are not
   recomputable from the bundle alone; they are proved instead by
   `test_generated_golden_matches_real_engine_output`, which rebuilds both
   goldens from the fixture CSV and fails on any differing byte. That test is
   the reason these files can be called engine output at all.
5. **Domain invariants.** Independently of the leaf walk, the per SKU tuple of
   decision, decided by, eligibility, band at decision, demand class, ABC
   class, rank by volume, volume share, scope, refusal code, resolution options
   in order and quality finding codes in order is extracted from both documents
   and compared as a sequence. The routing portfolio summary, the portfolio
   quality band and the whole classification result are compared outright. A
   second, differently shaped route to the same answer, so a bug in the leaf
   walk cannot hide a routing or classification change.
6. **The input did not move.** The recorded source block, including the dataset
   digest, must be unchanged, so the copy change is not standing in for a
   changed fixture.

Run it with:

```
cd forecast-app
PYTHONPATH=. python tools/verify_golden_copy_only.py claude/band-2-10-stories-xvxeif-2.10.4
```

It reports 13 `action` and 3 `detail` strings changed in the bundle, no copy
change at all in the manifest, hashes changed in both, and nothing else.

**The proof was itself proved able to fail.** Seven defects were planted in the
new golden one at a time and every one was refused, each by the check meant to
catch it: a moved volume share (check 2), a reworded routing reason (check 3),
a reordered resolution options list (check 3), a hand-edited bundle digest
(check 4), a changed routing decision (checks 2, 3 and 5), a changed source
digest (checks 4 and 6), and an added field (check 1). Each was reverted.

The regenerated files were also compared leaf by leaf

## 2. The rule

> Assay reports what the data shows. Where it tells a planner to act, it may
> only tell them to look at something or ask someone. It may never tell them to
> change a number, because it does not know their lead time, service target or
> costs.

## 4. The rule is now a control, not a proofread

`forecast-app/tests/test_advice_rule.py` reads every action out of real engine
output, not out of source, and refuses two things:

- **A sizing or setting imperative.** Assay telling a planner what to do to one
  of their own figures. Sizing a buffer needs a lead time and a service target
  Assay does not hold.
- **A claim about forecast accuracy.** At the point these strings are written
  no forecast has been run.

It is deliberately narrow. CLAUDE.md section 8 warns that a banned phrase list
which fires on legitimate copy gets ignored, which is worse than none, so the
scan matches imperative forms only. A test asserts that **the product owner's
own replacement text passes**, so a future tightening that would refuse the
sentence this story exists to keep fails immediately.

Two further tests hold the ground: the five withdrawn phrases may not reappear
in any of the five files that carry copy, and the sentences the brief names as
working must survive.
