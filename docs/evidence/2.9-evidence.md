## 2. Story 2.9.1, one `:root`

There were two `:root` blocks. The first carried the abandoned Claude Design
palette and the second overrode three of its values. The three overridden
values were dead. The other five were not: `--bg`, `--muted`, `--good`,
`--warn` and `--bad` were declared **only** in the first block, so deleting it
outright, which is what "delete the dead first `:root` block" reads as, would
have taken the three status colours with it and failed
`test_status_colours_match_assay` on the way out.

They are now one block, carrying every live value once.

Because custom properties resolve at use time from the final cascade value,
every `var()` in the file already saw the second block's values. Consolidating
therefore changes nothing that renders, and section 4 below shows that it
did not.

## 3. Story 2.9.2, muted is `#66615f`

`--muted` moved from `#68615e` to `#66615f`, the marketing site's
`--color-text-muted` in `tokens.css`.

**Recorded so the next reader knows it was settled rather than drifted.** The
two products deploy from separate Vercel projects and cannot share a token
file today, so the value is duplicated by decision, the same arrangement
already in place for the three status colours. The site's value wins because
the site is where the tokens are lifted from.

Contrast did not regress. It improved slightly everywhere it is used:

| Muted text on | Before `#68615e` | After `#66615f` |
| --- | --- | --- |
| Page ground `#f3f2f2` | 5.43:1 | 5.46:1 |
| Panel surface `#eae9e9` | 5.01:1 | 5.04:1 |
| Paper `#ffffff` | 6.07:1 | 6.10:1 |

194 text readings across the app moved from one to the other, and the count is
identical on both sides, so nothing gained or lost the muted treatment.

## 4. Story 2.9.3, every control paints its own label and its own corner

This is the iOS blue button defect, the one fixed on the marketing site on
6 September and recorded in `PROJECT_HANDOFF.md` as "far worse in Assay".

**It was worse.** Measured in Chromium at 1440px, across ten screens, before
any change:

```
252 of 397 visible control readings computed color: rgb(0, 0, 0)
```

against an app ink of `rgb(63, 61, 59)`. That is the platform default, not an
app value. It covered every primary button, every text input, every select,
every textarea, all 34 column sort buttons, the filter chips in both states,
the run pills and the classification matrix cells.

After:

```
0 of 397
```

The values chosen:

| Control | Label now | Why |
| --- | --- | --- |
| Anything on an accent fill | `--ink-deep` | 5.52:1. The site settled on this same value for the same reason. White would be 3.18:1 and fails |
| Everything else | `--text` | The app ink, 8.92:1 on a panel and 10.81:1 on paper |
| `.term`, `.matrix-cell:disabled`, the tabs | unchanged | Already declared explicitly. Left alone |

`border-radius:0` is now declared on each control rather than resting on the
universal `*{border-radius:0!important}` rule, which stays as the backstop.
Every radius reading was already `0px` and every radius reading still is.

`appearance:none` was added to `button` only, matching the site fix exactly.
It was deliberately **not** added to `input`, `select` or `textarea`: the site
kept `appearance:auto` on `select` because neutralising it removes the
dropdown arrow on every platform, and neutralising the inputs would change
what the date and file controls do, which this brief puts out of scope. The
screenshots confirm the date picker and the dropdown arrows survive.

## 8. What was not done, and why

**No iOS check.** The browser evidence above is Chromium at 1440px on Linux.
The defect this story fixes is an iOS one, and iOS has not been checked. It
cannot be from here. The fix is the same one the marketing site shipped for
the same defect, and the computed values are now app values on every control
rather than platform defaults, which is the condition that produced the blue
label. **That is an argument, not a confirmation.** Someone with a device
should open the Preview and look at the orange buttons, the filter chips and
the run pills before this merges.

**The abandoned palette is still painting two charts.** Twelve raw hex
literals of the old accent, old ink and old muted are in the chart drawing
JavaScript on the single file diagnostic screen. Band 2.9 named the `:root`
block, so they were left. This is Q6 in
`docs/assay-theme-open-questions.md`, with a recommendation.

**Five unused tokens were carried forward rather than pruned.** Q7, same file.

**No Preview and no Production check has run.** Section 6 of the workflow
wants both, and `PROJECT_HANDOFF.md` gets its merge and deployment evidence
after the merge, not before. Nothing above claims otherwise.
