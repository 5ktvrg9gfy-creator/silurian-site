# Story 1.3 forecast determinism measurement

Status: implementation and deployed Preview measurement complete.

## Measurement method

The same fixed input, effective options and deployment are run through BigQuery `AI.FORECAST` ten times. Every query sets `use_query_cache` to false. The measurement is accepted only when the returned BigQuery job metadata reports `cacheHit: false` for all ten jobs.

Every forecast point is compared with the first run. Maximum absolute and percentage differences are recorded. Where the first-run value is zero, only the absolute difference is used, the point is excluded from the percentage statistic, and it is counted in `zero_denominator_points`.

The implementation is in `determinism.py`. It fails closed if any result came from cache or if the provider returns inconsistent horizons.

## Deployment procedure

1. Deploy the Story 1.3 branch with `BIGQUERY_LOCATION` set to the approved UK or EU region.
2. Run the fixed synthetic canary once. Canary values are rounded to six decimal places before hashing so immaterial managed-service floating-point noise does not present as model drift. Set `TIMESFM_REFERENCE_BASELINE_SHA256` to the returned reference output hash.
3. Run `measure_forecast_determinism` over the approved fixed measurement series on the deployed BigQuery provider.
4. Confirm that all ten job records report `cacheHit: false`.
5. Store the resulting JSON as `TIMESFM_DETERMINISM_JSON` in the deployment environment.
6. Re-run a forecast and confirm the downloaded manifest contains the measured class and complete measurement block.

For a controlled Vercel measurement, set `TIMESFM_MEASURE_DETERMINISM=1` on the target Preview only, run `tests/run_manifest_fixtures/timesfm_reference_series.csv` once, capture the determinism object from the returned manifest, store it as `TIMESFM_DETERMINISM_JSON`, then remove the measurement flag. The flag must not be enabled in Production.
