# Story 1.4 contract: reproducible and re-openable runs

Status: approved for implementation on 30 August 2026.

## Purpose

Story 1.4 adds a portable confidential run bundle, a read-only reopen path, and an explicit reproduction comparison. The manifest remains the client-data-free proof. The bundle is the evidence, contains client data, belongs to the client, and is never stored server side.

## Manifest 1.2 correction

The content fingerprint excludes deployment-only identity: `app_version`, `git_commit`, `container_image_digest`, run identity and all timings. It includes source identity, effective options, stage engine versions, model identity, key calculation libraries and region.

Integrity is calculated in this order:

1. Clear both integrity hashes, remove run identity and timing, and calculate `content_fingerprint_sha256`.
2. Write the real fingerprint into the manifest.
3. Clear only `manifest_sha256` and calculate it over the manifest containing the real fingerprint.

The manifest schema is version 1.2. Story 1.3 forecast safeguards remain required whenever a forecast stage ran. Quality-only bundles contain validation and quality stages only.

## Bundle rules

- Bundle schema version is 1.0 and unknown versions are refused.
- The required confidentiality statement appears before the manifest and results.
- Results contain exactly the stages recorded in the embedded manifest.
- Import verifies the bundle hash, embedded manifest hash, copied manifest hash and copied fingerprint.
- Bundle hashing canonicalises integral JSON numbers, so a browser serialising `95.0` as `95` does not invalidate an unchanged bundle.
- A failed integrity check is refused and never repaired.
- Reopen renders recorded values only and calls no validation, quality or forecast engine.
- Engine version differences are stated without changing the recorded result.
- The application does not write bundles to server-side storage or logs.

## Reproduction outcomes

- `reproduced`: deterministic stages and any forecast output match exactly.
- `reproduced_within_tolerance`: validation and quality match exactly and the forecast is within the measured Story 1.3 tolerance.
- `differs`: versions and options match but deterministic output differs, or forecast output exceeds tolerance.
- `not_comparable`: stages, engine versions, effective options, relevant environment or model identity differ. Forecast determinism class `unknown` is also reported as not verifiable.

Canary `checked_at` is evidence timing and is excluded from model identity comparison. Canary input/output identity and status remain part of the comparison.

## Golden boundary

`tests/run_bundle_fixtures/run_bundle.golden.json` and its embedded manifest are generated by the real validation and quality engines. `tests/quality_fixtures/expected_quality.json` is not regenerated. The generator refuses to write the goldens unless every expected metric, tolerance, band and required finding matches that independent target.
