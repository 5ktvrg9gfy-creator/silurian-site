# Story 1.6 open questions

Status: all implementation questions are closed.

## Q1. Which stage owns descriptive demand-history findings?

Decision: quality owns `HISTORY_TOO_SHORT`, `SERIES_DISCONTINUED`, `SERIES_STALE`, `ZERO_VS_MISSING_AMBIGUOUS` and the single-observation condition. Validation decides only whether processing may continue.

## Q2. How are unresolved date-order and contradictory date-format evidence separated?

Decision: use `DATE_ORDER_UNRESOLVABLE` when numeric date order cannot be inferred. Reserve `DATE_FORMAT_AMBIGUOUS` for contradictory day-first and month-first evidence.

## Q3. May an invalid date contribute date-order evidence?

Decision: no. Invalid dates raise `DATE_INVALID` and are excluded from order inference.

## Q4. How is CV squared calculated?

Decision: use the population estimator over non-zero observations. Return null below three non-zero observations. Record both choices in the quality result and manifest.

## Q5. Is `SINGLE_OBSERVATION_SERIES` a separate quality code?

Decision: no. `HISTORY_TOO_SHORT` and the not-usable band already prevent a one-point series from proceeding. Adding a second code would duplicate the same limitation.

## Q6. How is cross-stage ownership enforced?

Decision: permanent tests compare validation and quality code ownership and reject duplicate codes in the real quality endpoint payload. The test was proved by temporarily reintroducing a duplicate and observing the build fail.
