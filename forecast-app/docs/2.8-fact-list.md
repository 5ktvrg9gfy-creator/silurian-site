# Band 2.8 fact list

**This is an input to band 2.8 in the product owner's backlog. It is not a client-facing statement. It must not be published, and it must not be linked from the application.**

It is a bare list of the facts a data handling statement would have to cover, with each one marked verified or not. There is no wording here, no draft statement and no recommendation.

Compiled 3 September 2026.

## Verified in this session, by reading the code and the configuration record

- What the application receives: one CSV upload plus form fields for analysis date, grain and routing resolutions.
- Which stages run entirely in-process and call nothing external: validation, quality, classification, routing.
- Which paths call an external service: `/api/analyse`, `/api/analyse-portfolio`, `/api/reproduce-bundle`.
- What is sent to BigQuery: two arrays as query parameters, dates and quantities. No SKU, no filename, no other column, and no identifier in the query text.
- Processing region: `europe-west2`, London, pinned and enforced by test.
- Query caching disabled, and a reported cache hit stops the run.
- No application database and no object store.
- The confidential bundle stays in the browser; there is no server-side bundle storage, enforced by test.
- The run manifest carries hashes, counts, codes and options only, no client identifiers, enforced by several tests.
- What the application itself logs: request paths and status codes, and an error line carrying no payload. The access password appears in no log.
- Access control: one shared password, a signed session cookie, no user accounts, and therefore no record of who entered it.

## Not verified, and each one needs an answer before it can appear in a client-facing statement

- **Not verified.** BigQuery anonymous result table retention, up to 24 hours. Stated in the 1.5 position from provider documentation, not independently confirmed.
- **Not verified.** BigQuery job metadata retention, six months, including the query and its parameters. Same status.
- **Not verified.** Vercel runtime log retention on the current plan.
- **Not verified.** Vercel's platform backup position as it applies to transient function request data. This is the outstanding written provider assurance, and it is 2.8.1.
- **Not verified.** The FastAPI multipart spool: whether and when it reaches the function filesystem in the deployed runtime, and what removes it.
- **Not verified.** Whether personal data is present at all, which decides the controller, processor and sub-processor roles. The 1.5 position says this needs qualified review.
- **Not verified.** The sub-processor list and the international transfer position for both Google and Vercel.
- **Not verified.** Whether masked SKU codes carrying real volumes are pseudonymised rather than anonymised. The 1.5 position asserts pseudonymised; it is a legal characterisation, not a code fact.

## The shape of it

Everything about what the application does is verified, and almost nothing about what the two providers retain is. That is why 2.8.1 is the long pole, and it is also why the current landing sentence stops where it does. It says where the data goes, which is verified, and says nothing about how long anyone holds it, which is not.
