# Build brief: story 2.0, a tool rather than a page

Silurian Assay. Structure story, before sprint 2 begins.

Short brief, because the specification is the published mock rather than this document. One build session, timeboxed.

---

## 1. What this is

The output today is one long scroll: form, validation block, provenance panel, quality portrait, per SKU table, exceptions. That is a document pattern, and it is why the tool reads as a page.

Sprint 2 adds a nine box and method routing, sprint 3 adds the value added stairstep, sprint 4 adds money figures. Each of those lengthens the scroll and each becomes rework. This story stops that before it starts.

**This is structure only.** Visual polish stays out of scope until story 5.1, so the screen and the branded export are designed as one system. No engine changes, no new findings, no new calculations. Every number and every phrase already exists in today's output.

---

## 2. The specification is the mock

The published workspace mock is the acceptance criterion. It is interactive, it uses the real mixed portfolio output, and it carries its own reasoning: the **Design notes** button in its masthead puts eight numbered marks on the page keyed to a panel explaining each structural decision. Read that panel first. It explains why, which this brief does not repeat.

Its CSS token block is lifted from `index.html` on the marketing site, so tokens are copied rather than reinterpreted. Do not re-derive them.

**What to take from the mock:** layout, component structure, interaction behaviour, tokens, copy tone, empty states.

**What not to take:** its data is hardcoded, it has no routing, and its filter and sort logic is illustrative rather than production code.

---

## 3. The seven items

1. **Persistent run context.** Source, analysis date, grain, verdict, band and run id stay visible at every scroll position and on every panel. Today they sit in a block you scroll past, so a client three panels down cannot see which file produced what they are reading.
2. **Switchable panels rather than one scroll.** Validation, quality, forecast and provenance become peers.
3. **The grid becomes the work surface.** Sort by any column, filter by band, search by SKU. The exception list stops being a separate section and becomes the caveated and not usable filters.
4. **State encoded twice on every row.** Orange as a mark on caveated lines, orange as a field on not usable ones, nothing on clean. Plus the written band on every row, so nothing depends on colour.
5. **Detail opens beside the data.** Selecting a line opens its findings without losing your place. What, so what, do this, in that order.
6. **Empty states say what happened.** The forecast panel names the eligible and excluded lines and offers the next action rather than showing nothing.
7. **Every new output is a self-contained panel component.** Owns its heading and body, knows nothing about what sits above or below. This one outlives the session: it applies to all sprint 2, 3 and 4 work, and it is now in the permanent definition of done.

---

## 4. Design system notes, since these are easy to get wrong

- **One typeface.** Archivo, weight 800 for display, with `font-feature-settings: "tnum" 1` for figures. There is no mono in the system. Hashes and SKU codes use Archivo with slight letter-spacing. If that proves unreadable at scale, raise it rather than introducing a second face quietly.
- **Zero radius everywhere.** The system has `--radius-sm/md/lg` all set to 0.
- **Structure is drawn, not floated.** 2px solid rules on the seams, 1px hairlines inside tables. Shadows exist in the system but are used sparingly. This is the single biggest difference from a generic dashboard.
- **The grounds invert what you might expect.** Page is `#f3f2f2`, surface is `#eae9e9`, so panels sit darker than the page rather than lighter.
- **The ink field is a pace change.** The run context bar uses `#1a1918`, the stone's darkest facet, with paper text.
- **No dark mode.** The system is print derived and commits to paper. Paint every colour explicitly rather than relying on inheritance.
- **The wordmark is Silurian Assay**, with the stone mark from `logo-stone.svg`.

---

## 5. Copy

Match the site's register: short, declarative, no hedging. "Independent programme and project management." "Tell us what needs to land, and by when." Hold every string in the interface against that.

Two words in the current output are yours rather than a planner's. **Grain** is data modelling vocabulary, planners say monthly or weekly. **Manifest** and **bundle** are precise and worth keeping, but need a plain gloss on first use.

---

## 6. Acceptance

1. Run context is visible on every panel at every scroll position.
2. Switching panels does not lose grid state: filter, sort and search survive.
3. The grid sorts on every column, filters by band, and searches by SKU.
4. Every row carries both a colour treatment and a written band. Removing colour entirely leaves the table fully readable.
5. Selecting a row opens detail without navigating away, and closing returns to the same scroll position.
6. The forecast panel with no model run names the eligible count, the excluded count and the reasons.
7. Each panel is a component that can be rendered in isolation with no knowledge of its siblings. Prove it by rendering one alone in a test.
8. No engine call changes. The same run produces the same manifest, quality result and bundle hashes as before this story.
9. Tokens match `index.html`. No invented colours, no radius, no second typeface.
10. Keyboard: tabs reachable, grid sortable by keyboard, drawer closes on Escape, focus visible throughout.

---

## 7. Timebox and the stop rule

One build session. **If it overruns, ship what is done and move to 2.1.** Polish is explicitly deferred, so there is no reason to keep going. The risk this story carries is that layout work quietly eats sprint 2 while the diagnostic gets no closer to a saleable finding, and the timebox is the only control against it.

Questions go in `docs/2.0-open-questions.md`, same format as before: what it blocks, your recommended default, cost if wrong.
